# 复习分析思想（本专家承载的内核）

> 本文件是 `review-analysis` 这个专家真正「承载的思想」：不是某个按钮，而是「如何把一堆复习资料，变成可复习、可出题、可闭环的结构」。`bin/driver.js` 只是这套思想的离线执行体。

## 一、边界清晰：先划材料边界，再谈分析

- 分析前必须**显式指定项目/书**；没指定的，默认不读。
- 分层（layer）：资料按重要性分 1..N 层，1=核心提纲层。分析/出题时高层权重更高。
- 思想落点：「你让它分析什么，它才分析什么；边界之外的事，默认不做。」

## 二、忠实原文：不编造、不替你写

- 本地引擎只从资料原文抽重点与出题，不产生新知识。
- 大纲（`syllabus.buildBookOutline`）是规则版自动整理，标题明确标注「仅供参考」。
- 思维导图节点带 `summary`（来自原文）与 `children`（层级），`related` 只连**真实共同考到**的两知识点（co-question），不凭空造关系。
- 思想落点：「脚本是剪刀和胶水，不是作者。结论必须能在原文里指出来源。」

## 三、一轮轮驱动：think→invoke→observe

- 不一次性把全部书塞进一个巨型调用。每轮处理一个回转窗口（`--rounds`），进度记盘（`REVIEW_ANALYSIS_STATE.json`），下次续做。
- observe 阶段把本轮结果聚合进「全展开图」，让认知是**累积**的，而非每次从零——重跑同一本按 id 覆盖，新轮追加。
- 思想落点：「大任务切成可验证的小轮；每轮都能停下来看一眼，再决定下一轮往哪走。」

## 四、闭环复习：分析 → 出题 → 批改 → 薄弱 → 再练

- 分析产出知识点与题目；出卷练；批改得对错；错题累积成「薄弱地图」；leech（反复错）优先复习；到期队列串起每日复习。
- 自评只改排程，不刷错次数；反馈记录掌握程度，但**绝不**把模型自评当成又一次交卷。
- 思想落点：「复习的终点不是『做过』，是『到期还能做对』。闭环比单次正确更重要。」
- 注：出题/批改/薄弱地图由 review-library 主程序闭环提供，本专家负责前段的**离线结构化分析**。

## 五、圆满格式：人读 + 机读同源

- 同一份数据派生两种形态：Markdown（人读结论）+ 全展开 JSON（机读/前端下钻）。
- 全展开 = 构建期就把整棵图铺开（不是前端折叠后才懒加载），agent 与可视化都能直接消费。
- 思想落点：「交付物要让人一眼看懂，也要让机器直接能吃。两种形态，一份真相。」

## 六、安全与诚实

- 零云端硬约束：所有分析走本地 `lib/*`，前端 CSP `connect-src 'self'`，绝不外发。
- 降级不撒谎：模型不支持看图 → 自动关对应模块，并明说，不假装成功。
- 密钥只活在本标签页/环境变量，不落盘、不进日志、不进截图。
- 思想落点：「能做的做，做不了的明说做不了。安静地假装成功，比报错更坏。」
