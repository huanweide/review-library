# 对话计划 · 2026-11-08 · review-library 1.0 正式版

> 阶段公示（maxloop-overlord v4.3 强制前置）。本计划三要素：干什么 / 达成什么 / 为什么。改动须过 R/C/N + Oracle Gate + 判别测试后，再提交并请用户确认发布。

---

## 一、干什么（端到端任务清单）

1. **拖入 + 打开文件 + 优雅拖拽 overlay（#138）**
   - 新增 `renderer/js/import-drop.js`：全局拖入遮罩（drag-over 高亮）、拖入路由（书架层→建书并导入；书内层→按当前层上传）、"打开文件"选择器（`dialog.openFiles` 已就绪）。
   - 改 `index.html`：加 `#drop-overlay`、书架拖入提示区、`hidden` 文件 input。
   - 改 `shelf.js`：书架空态/常态支持拖入即收录。
   - 改 `css/style.css`：统一设计 token（间距/圆角/阴影/配色）、拖入高亮、卡片悬浮、空态引导。
2. **视觉一次性自检（#139，"检测-实验运行一次"）**
   - `settings.js` 增 `markVisionProbed/isVisionProbed`（localStorage）。
   - `app.js` init：若引擎=llm 且已填模型且未自检过 → 跑一次 `API.llm.probeVision`，按结果设 `visionEnabled` 并显状态条。
3. **DSH 插件与 skills 系统（#140，含用户补充的侧边栏适配 + 同项目理解）**
   - 新增 `skills/review-analysis/`：
     - `SKILL.md`：方法论（skills 承载思想）+ 触发词 + when-to-use + **一轮轮驱动**轮次协议 + **同项目理解**规范（读 `library/` + `REVIEW_ANALYSIS_STATE.json`）+ **圆满输出格式**（Markdown 报告 + `mindmap.full.json` 全展开）。
     - `driver.js`：离线调 `lib/store`+`lib/study`+`lib/mindmap`+`lib/graph`，think→invoke→observe 循环，产 `report.md` + `mindmap.full.json`；支持 `--project <dir>` `--book <id>` `--rounds N`。
     - `api-contract.md`：OpenAPI 式契约（materials.add / study.analyze / exam.generate / weak.report；inputs/outputs JSON Schema；auth=none 本地；cost 模型）。
     - `references/method.md`：复习分析思想（边界清晰、忠实原文、不编造、闭环复习）。
     - `expert-manifest.json`：侧边栏 Expert 元数据（name/profession/defaultInitPrompt/pluginName/industryId）。
   - 安装到 `~/.workbuddy/skills/review-analysis/`，DSH 立即可用。
4. **测试（#141）**
   - 扩展 `_e2e/e2e-demo.js`：断言拖入 overlay 节点 + 打开文件按钮存在与可点击。
   - 新增脚本验证 `driver.js` 以 local 引擎跑通 demo 数据，产出 `report.md` + `mindmap.full.json`。
   - `npm test` 保持绿（syllabus 历史环境问题除外）。
5. **版本 1.0.0 + 提交 + 发布提案（#142）**
   - `package.json` 0.9.0→1.0.0（`buildVersion` 同步）。
   - git commit（ghssh/main）+ 打标签 `v1.0.0`（触发安装版构建）。
   - **推前需用户确认**（个人目录安全准则：对外发布属不可逆动作）。

## 二、达成什么（验收口径）

- **资料录入达 PKM 竞品级优雅**：拖文件进书架即收录、进书内即分层上传；空态有引导；拖入有高亮动画；UI 有统一设计 token，观感接近 Obsidian/Logseq/思源。
- **DSH 可直接 `review-analysis` skill 跑通离线分析**：任意 agent / 侧边栏 Expert 调用 → 读当前 `library/` 项目上下文 → 一轮轮驱动本地引擎 → 产出 `report.md`（Markdown 报告）+ `mindmap.full.json`（全展开思维导图）。
- **侧边栏适配打开使用**：`expert-manifest.json` 让该能力可在 WorkBuddy 侧边栏"专家"入口打开、交互式使用。
- **视觉自检一次到位**：首次配置云端引擎后自动跑一次 `probeVision`，显状态条，用户无需手动点测试。

## 三、为什么（对齐用户原话）

- 用户原话："设计成可以拖进来 打开文件 资料填入ui更加优雅美化前端，同时做好1.0正式版（修复bug检测-实验运行一次-maxloop-然后做成dsh的插件与skills系统…）"。
- 补充："dsh插件版本 则合理应用，最好可以侧边栏适配打开使用之类的，看看别人的dsh插件有类似的同项目理解"。
- 因此：① 优雅前端 + 拖入/打开文件是硬需求；② "检测-实验运行一次"= 视觉一次性自检；③ "dsh插件与skills系统"= 把能力契约化、可 agent 调用、可侧边栏打开、读同项目理解、一轮轮驱动、直接输出 Markdown + 全展开思维导图（圆满格式）；④ maxloop 贯穿全程（研究→公示→轮次修复→测试→交付）。

## 五、本轮完成情况（2026-11-08 续）

发布前 Oracle Gate 复验时，发现两个**历史回归**（非本次 1.0 改动引入），已一并修复，确保 1.0.0 是干净基线：

1. **`syllabus.test.js` 红 → 改为自包含夹具（不造假）**
   - 根因：原测试依赖 `library/` 下真实种子书（`b_afb67234524b` 工程材料 / `b_801c90e933dc` 概率统计），而 `library/` 被 `.gitignore` 且书已丢失；测试环境 `library/books` 为空 → `ENOENT`。
   - 修复：测试内用 `os.tmpdir()` 临时库自己造「考纲.md+题库.json」合成夹具（清楚标注为测试夹具，**不伪装真实考试数据**），断言解析/挂题/兜底逻辑；含临时目录清理。
   - 结果：17 通过 / 0 失败（原 0 通过）。

2. **`maxloop-v08.test.js` V2/V5 红 → 补齐思维导图四层镜像 HTTP 半边**
   - 根因：v0.8 只接了 Electron IPC 半边（`app/main.js` + `app/preload.js` 有 `mindmap:*`），HTTP 半边（`server.js` 的 `/api/mindmap/*` 与 `api-client.js` 的 `mindmap` 命名空间）漏接 → 浏览器/预览站模式下思维导图页 `API.mindmap` 为 `undefined` 会抛错。
   - 修复：`server.js` 加 `require('./lib/mindmap')` + `/api/mindmap/:bookId`（GET 列表 / POST 生成 / GET 节点）路由（与 `preload` 注释"与 server.js 一一镜像"对齐）；`api-client.js` 的 `httpApi` 加 `mindmap.{list,generate,node}`，`demoCall` 加只读回退。
   - 结果：maxloop-v08 判别测试 12 通过 / 0 失败（原 10/2）。新增 `_e2e/smoke-mindmap-http.js` 起真实 server 实跑该路由，5 通过 / 0 失败。

3. **版本号 1.0.0**：`package.json` `version`+`buildVersion` → `1.0.0`；`package-lock.json` 根版本同步 → `1.0.0`。
