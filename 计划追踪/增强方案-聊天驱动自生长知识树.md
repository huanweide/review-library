## 0. 一句话定位

把 review-library 从「先导入整本书 → 整体分析 → 出卷」升级为「**你发题（文字/截图）→ Agent 讲解答 + 智能归类 → 你确认位置 → 长进一棵概念/题型混排的自生长树 → 点节点看详解+上下游+全部题型+题图 → 间隔复习不烦**」。本质是 Graph-Chat 的「对话中建图」+ GraphRAG 的「LLM 抽实体关系」+ Karpathy LLM Wiki 的「自生长可整理知识库」三者的**考试备考特化版**。

## 1. 权威参考锚点（已查证）

| 参考 | 是什么 | 与本方案关系 |
|---|---|---|
| **jacinli/graph-chat** | 中文「对话过程中自动构建和更新知识图谱」智能对话系统（OpenAI API + vis-network） | 几乎一字不差对口：聊着聊着图就长出来 |
| **microsoft/graphrag** | LLM 从文本抽实体+关系→知识图谱，社区检测+摘要，模块化管线 | 权威「LLM 建图」引擎范式；本方案是交互式+确认门版本 |
| **Karpathy LLM Wiki** | 编译器范式：LLM 当纪律严明的知识库维护者，人类可读、增量更新、schema 协同演进 | 「自生长、能整理、能存储、越用越准」的范式基础 |
| **Tana / Mem / Logseq** | 2026 second-brain 三档：自生长 / AI 自动连线 / 本地大纲+闪卡 | 「自生长」+「复习不烦」（Logseq 闪卡≈本工具已有巩固卷） |
| **费曼+主动回忆+间隔复习（5 层）** | 概念卡→主动回忆提问→个人知识图谱→间隔复习 | 直接对应「复习而不感到厌烦」 |

**本方案的独创点（上述参考都没做）**：① 概念—题型混排树（题型是一等节点）；② 确认门（弹位置让你确认才归档）；③ 题图智能截取（含跨页抓图贴右边）；④ 开关（关掉就是纯对话）+ 纠偏（新建类型/大类、把整类题搬进已建好的书）。

## 2. 当前状态 vs 目标（对照）

| 维度 | 当前 v0.8/v1.5.0 | 目标 |
|---|---|---|
| 知识来源 | 导入整本书 → 整体分析 | 问答即输入：发题/截图 → 逐题归档 |
| 导图内容 | 中心辐射图；规则版 summary 常空（`mindmap-ui.js:107` 显示「暂无详解」）；题型竖排、不带图 | 点节点出详解 + 上游链路 + 下游分类 + 该节点下全部题型横向卡片 + 题图 |
| 归类方式 | 人工导入时分层 | Agent 智能归类 + 弹位置确认 + 可纠偏/搬书 |
| 题型载体 | 题库.json，练习页出卷 | 直接挂到树的节点下，随树生长 |
| 图来源 | 考纲.md + 题库.json（或 API 生成） | 对话归档 + 既有书库双轨并存 |

## 3. 核心数据模型变更（节点 schema）

现有 `lib/mindmap.js` 节点为 `{title, summary, children[], questionTypes[], related[]}`，缺「概念/题型区分、上游链路、题图」。扩展为：

```
MindNode {
  title, kind: 'concept' | 'qtype',   // 概念 or 题型（混排关键）
  summary,                             // 详解（规则版也填定义，不再空）
  parent,                              // 上游（单一父，构成树）
  children: [title],                   // 下游分类
  questions: [{ id, stem, answer, explanation, figure?: {src, page?, note?} }],
  related: [title]                     // 跨节点双链（保留）
}
```

题型节点（`kind:'qtype'`）可直接挂在概念节点下，也可在概念节点末端直挂（对应「B变化 后面可以接题型」）。**不破坏既有 `analysis.json`**：旧数据无 `kind` 默认按 concept 渲染，向后兼容。

## 5. 分阶段切片（建议顺序）

1. **MVP（最先做）**：聊天入口 + 发题→讲解答→弹位置确认→长进树 + 开关。复用最多、最快验证核心想法。
2. **详细版思维导图**：直接解「只见其表」痛点（§4.4 + 预览页原型）。
3. **题图智能截取**：拍题体验（§4.5）。
4. **自生长/纠偏/搬书**：让树能自我修正、跨书整理（§4.6）。

## 6. 验收标准（不变量）

- 判别测试新增：① 关掉自动归档时发题**不**写库；② 确认门前不落盘、确认后才落盘（原子）；③ 题型节点可直挂概念末端；④ 旧 `analysis.json`（无 `kind`）仍正常渲染不报错；⑤ 题图截取在「图在下一页」时仍归到该题（用真实多页 PDF 样例验）。
- e2e 新增：聊天发题→确认→树新增节点→点节点出详解+全部题型+题图；粘贴图片进入对话；开关切换后行为正确。
- 密钥纪律维持：题图/对话文字绝不进日志、不进错误回显（沿用 `lib/llm.js` 的 `scrub()`）。

## 7. 诚实边界 / 已知限制

- 「智能归类」是 LLM 建议 + 你确认，**不是自动全信**；判错走纠偏，不静默覆盖。
- 题图跨页抓取依赖题干/图的可解析结构，纯扫描乱版 PDF 可能抓不准，需标注「疑似图在 Px」而非硬判。
- 模型解答质量 = 你填的 API/模型质量；本地引擎不进此链路（保持零外链原则，聊天走同源 `/api`）。
- 自生长树与既有「整本书整体分析」**并存不互斥**：导入整本书仍走旧链路，问答归档走新链路，共用 `library/` 与 `store.js`。
