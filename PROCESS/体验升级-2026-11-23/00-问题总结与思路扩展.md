# 一、先定规矩：这次改什么、不改什么

用户原话的关键约束：**「搞之前先确保提示词和用处没有相似点，有意义」**。
翻译：不要造重复轮子。凡是提示词里已经写了、数据里已经有的，先查出来，缺的才补。

地基核对结论（逐条带证据）：

| 用户以为 | 实测根因 | 证据 |
|---|---|---|
| 「答案太简单，要让 LLM 写、应用教学提示词」 | **提示词已经写了完整教学要求**，数据也齐全：14/14 题都有 answer、solution（平均 4.4 步）、rationale、pitfalls；首题 answer 带破折号解释+4步推导+rationale 写清"从哪切入/为何用此法/错误做法为何不行" | `core/analyze.js:78` desc 三层递进、`:109-111` rationale 至少2句、`scripts/build-lesson-cards.mjs:131` 零基础三问；`analysis.json` 实测 cnt |
| 「讲解面板点开没清晰解释」 | 面板七个步骤的**题型/真题/答案/易错/深挖全靠 analysis 字段**，但讲解面板走的是 `questionsFromBranch` 回退取题，取到的题和节点不对位；深挖这次没跑（`deepDive: 无`） | `workbench/src/bookspace.js:1160-1242` |
| 「答题界面没法选择」 | 选项是纯文本 div，无 onclick、无提交判分 | `bookspace.js:765` `el('div',{class:'bs-q-opt',text:o})` |
| 「有的题根本没图」 | 14 题 imageIds 只有 4 题非空；`attach-source-images` 只补"题干含图意词+同页唯一图"，"画出受力图"这类题的源页图不止一张/或无精确同页 → 没补 | 数据实测 4/14；`scripts/attach-source-images.mjs` |
| 「导图突兀拉伸跳转」 | `paint()` 每次 `canvas.innerHTML = ML.toSvg(...)` 整棵重建，无 transition；CSS 只有 `max-height:460px;overflow:auto`，无缩放平移 | `workbench/src/mindmap.js:246`、`style.css:284` |

**结论：真正的缺口只有三类**——①前端交互（导图动画/缩放、选项可点、思路按钮、阅读器）；②数据生产端的一个诚实缺口（题图配不齐、讲解节点与题不对位）；③幻灯片目前是"全部塞进去"，要改成"考点重要幻灯片按序"。**提示词不用重写，只要把已有的教学深度渲染出来。**

# 二、逐条推导（现象 → 根因 → 改法 → 验收）

## 需求 1｜导图丝滑动画 + 无界草图空间
- 现象：点节点/展开时整棵 SVG 瞬间替换，"突兀拉开拉伸与跳转"；界面固定宽度不能缩放。
- 根因：`paint()` 用 `innerHTML` 全量重绘（mindmap.js:246），零过渡；SVG `width:100%;height:auto` 写死（:249-252）。
- 改法：
  - 展开/收起：对新增节点做 CSS `@keyframes` 淡入+轻微位移（不重建已有节点则保留位置）；整棵重绘不可避免时，至少给 canvas 一层 cross-fade。
  - 无界草图：外层加 transform 容器（`scale`+`translate`），滚轮缩放、拖拽平移、工具栏 +/−/复位；点击命中要按变换后坐标反算（SVG 内部 g 的 click 事件浏览器会自动按变换命中，不用手动反算）。
  - 缩放状态进 `persistMapState`（新增 scale/tx/ty 字段，向后兼容旧状态）。
- 验收：真浏览器截图+eval 确认 transform 值变化、节点点击仍命中、展开有动画。

## 需求 2｜导图节点讲解要定义/方法/上下游/公式/做题方法论
- 现象：截图里"光滑铰链约束"面板——常考什么"模型没标"、真题"暂时没有"、答案"暂无"、易错"没有标注"、深挖"未做"。
- 根因：讲解内容全依赖 analysis 对应字段，而这次分析 `deepDive` 没跑；回退取题按分支，不按节点。
- 改法（**不重复造提示词**）：把已有的 desc 三层递进（是什么/怎么考/易错）**拆成独立可读的三段**，而不是一整句塞在"这是什么"；上下游关系从 `pointPath`（章>讲>知识点）渲染成"它在知识链上的位置"；公式/方法论从 desc 和题的 solution 里抽；确实没有的字段诚实说"资料里没有，不编"。
- 验收：点任一叶节点，面板至少给出定位链+定义+考点+可做题，空态文案只在字段真缺时出现。

## 需求 3｜题目答案要 0 基础看懂、应用教学提示词
- 现象：用户觉得答案简单。
- 根因：**数据不简单**（14/14 有 4.4 步 solution + rationale），是前端把 answer 和 solution 折叠了、rationale 用一行小字带过，看起来单薄。
- 改法：题型页答案区重排为教学卡片——「答案」+「分步解答（番号列表）」+「为什么这么想（rationale 独立成段）」+「易错点」+「零基础补一句定义」。教学提示词已有（desc 三层、rationale 三段式），前端把它**分层展示**即可，不重写提示词。
- 验收：真截图对照，一道题的答案区能看到 ≥4 步 + 独立 rationale 段。

## 需求 4｜答题界面可选择、确认、有答案
- 改法：选项改可点（radio 行为），点"提交答案"判对错（用 q.answer 首字符 A/B/C/D 对），显示对错+解析；保留"直接显示答案"给不想做的场景。判断题 A/B 同理。
- 验收：点选项→高亮→提交→对错反馈，真浏览器走一遍。

## 需求 5｜思路按钮（不给答案，给方法论）
- 用户定义很具体：计算题给方法论+定义；定义题给相近概念/上下游反刍，不给答案。
- 根因：现在 rationale 是"解题后复盘"，直接写在答案里，起不到"先想再给"的作用。
- 改法：新增"💡 思路点拨"按钮，独立于"显示答案"。内容优先级：①从 q.pointPath / desc 取该知识点的定义与相邻概念（反刍）；②从 q.solution 抽象出方法名（如"数受力点判二力杆"）而不给结论；③判断题/定义题只给相近概念对比。点它不给 answer。
- 关键：这是检索式重组，不是新生成——zero-cost、确定、可验证。
- 验收：点思路按钮看不到答案字面；点显示答案才看到。

## 需求 6｜左侧资料可点、就地阅读器、可改名
- 根因：bs-file 无 handler；无阅读器依赖。
- 改法：
  - 服务端加"取原始文件字节"端点（fileId → library/books/<id>/<file>，白名单限扩展名，防穿越）。
  - 前端点击 bs-file 打开阅读器浮层：PDF 用浏览器 `<embed>`/`<iframe>`（原生），Word 用纯文本抽取预览（`pdf-parse` 只管 PDF，docx 走提取后的 note/文本），PNG/JPG 直接 `<img>`；阅读器标题栏改名输入框，调现有 rename action；"内外侧都可改"=阅读器内和资料列表行内复用同一个 server 端点。
  - 先确认服务端 file 端点是否已存在（评审在查），有就复用。
- 验收：点资料→浮层出现且内容正确→改名→列表同步更新。

## 需求 7｜配图要准 + 幻灯片改考点重要幻灯片
- 配图：无关图（只有书名/软件界面截图）不该配。判据：图片 vision/transcript 里必须含与题干/知识点重合的实质词；纯封面/目录/软件 UI 过滤。`attach-source-images` 已有"同页唯一"约束，再加"内容相关性"。
- 幻灯片：从"全部塞进去"改为"考点重要幻灯片"——按章分组、按 pointPath 顺序、优先带图/重点标记（f.focus）的页；每页给一句"对应考点"。
- 验收：截图看题目配图相关；幻灯片页按章有序且标注考点。

# 三、执行顺序（依赖关系）

1. **先做数据层小修**（图题匹配加内容相关性、讲解面板字段对位）——纯确定性，零 API 成本，风险低。
2. **题型页交互**（可点选项+提交判分+思路按钮+答案教学化重排）——用户最新补充的重点，改动集中在一个函数。
3. **导图动画+缩放**（独立前端模块，改 mindmap.js + style.css）。
4. **资料阅读器**（需服务端端点，改动面最大，单独验证）。
5. **幻灯片考点化**（可复用现有 compose 数据）。
6. 每步跑门禁+真截图验证，最后统一升 SW 版本（前端改了不升版看不到）。

# 四、明确不做

- 不重写 `SYSTEM_PROMPT`——教学要求已存在，重写只增加漂移风险。
- 不改 `library/` 下任何数据文件的 git 状态——按仓库规则用户数据不入库。
- 不把无关图片硬配给题目；没有可信依据时诚实留空并说明。
- 不在这一轮引入新 npm 依赖（pdf.js/mammoth）——先用浏览器原生能力，不够再说。

## 关键判断（为什么没重写提示词）

用户要求「搞之前先确保提示词和用处没有相似点，有意义」。核对发现：
- `core/analyze.js:78` 已要求 desc 写「是什么；怎么考；最容易错」三层，
- `:109-111` 已要求 rationale 至少 2 句写清「从哪切入/为何用此法/错误做法为何不行」，
- `scripts/build-lesson-cards.mjs:131` 已要求零基础三问。

所以「答案太简单」的真根因是**前端把现成深度折叠/糊成一段**，不是没让 LLM 写。策略是把数据分层呈现，而不是再写一遍提示词让模型重跑（既费钱又会与已有字段冲突）。唯一新写的是 `study-hint.mjs` 的「思路点拨」——这是**新用法**（检索式、不给答案），与已有 rationale（解答后复盘）用途不同，不算重复。

## 诚实边界

1. docx/xlsx/pptx 靠浏览器原生预览；无法预览时明确给「下载查看」，不假装能读。
2. 整页扫描图里含多张子图（如 Q1 一页里有桁架图+两张现场照片）无法切分；图与题同页即算配准，这是来源的固有限制。
3. 9/14 道题本来就没选项（简答/论述），这些题不显示「提交答案」，直接看解析。
4. 510 行讲解面板的「真题」步骤对部分末端节点确实无题，显示诚实说明而非硬凑。
5. 幻灯片生成结果含 1 处模型占位词（「此处为…」类），界面已按 `placeholder` 检测诚实警告，未用样式掩盖。

## 收尾（2026-11-23 提交时补记）

七条全部落地，版本 `1.7.0` / SW `v30`。提交前又抓到两个「门禁假红」，不是功能问题但会污染证据，顺手修掉：

| 现象 | 根因 | 修法 |
|---|---|---|
| `core-practice.test.js` 28 条断言全绿却判套件失败（exit 3221226505） | Windows + Node v24 下进程碰过 `fetch`（undici）后硬 `process.exit()`，libuv 收尾抛 `!(handle->flags & UV_HANDLE_CLOSING)` | 改为 `process.exitCode` + 5 秒兜底硬退；子进程先等 exit 再 destroy stderr pipe |
| `core-http.test.js` 偶发 `fetch failed` / 「空书架」莫名变红 | 上一轮崩溃留下孤儿 server 占着 5191，`waitServer()` 连到了旧进程（root 不是本轮临时目录）；且子进程原先用 PATH 的 `node`（v22，与本轮 v24 ABI 不同） | 起服务前按端口查 PID 清孤儿；子进程改 `process.execPath`；`req()` 只对连接类异常重试一次；FATAL 时打印子进程 stderr |

判别口径没动：真 4xx/5xx 照旧红，重试只覆盖连接失败。
