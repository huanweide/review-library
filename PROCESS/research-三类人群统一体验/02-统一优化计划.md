# 三类人群统一优化计划（三者全满足 · maxloop 讨论轮 · 只计划不做）

> 日期：2026-11-27 ｜ 状态：**计划，未实施** ｜ 依据：`01-三类透镜问题清单.md`（三个独立 critic + Chair 亲验 + 真机走查）
> 统一命题：**把「一本书的分析结果」升级成「一份可改、可做、可存、可带的考点资产」**。
> 三类人不是三份计划拼盘：备考人要「做完能记住」、梳理人要「结构我能改」、存储人要「找得回不会丢」——
> 三者要的是同一个东西的三面，所以做成一条主线，每项都同时交代对三类人各有什么用。

## 一、统一主线（一句话讲清）

现在的产物是「模型读完书吐出来的一棵只读树」。要改成「**学生自己的考点资产**」：
模型给底稿 → 学生能改结构 → 原题能真做 → 做题结果进记忆曲线 → 一份包能导出、能打印、能备份、能找回。
四个环节环环相扣，缺一个另外两类人都不成立：

```
分析底稿(已有) → [新增]用户结构层 → [新增]题卡结构化 → [打通]进度挂原题 → [新增]考点包导出/备份
                  ↑梳理人               ↑备考人            ↑备考人              ↑存储人
```

## 二、五项改动（每项过 R/C/N + 对三类人的作用）

### 第 1 项 · 用户结构层（模型树只读，人工改动另存）

- **干什么**：导图节点可以重命名、增删改、拖拽换父、撤销重做。改动存成书级 `structure.json`，**不覆盖模型分析结果**；重新分析时以结构层为准合并。
- **R 合理**：`llm-config.js:10` 那类「契约写死但没接线」的教训反过来用——这里是把「用户是主人」写成数据层契约。markmap 13,303★ 只负责画，jsmind/mind-elixir 证明「画 + 编」是两件事。
- **C 正确（锚点）**：`core/analyze.js:70-76` 要求模型照搬不许创作；`fusion-decisions.md:38` 曾否决节点编辑；`workbench/src/mindmap.js:125-126` 排除了节点 pointerdown；`persistMapState` 只存视口。这些是当年「防模型乱改」的正确决定，但现在缺的是**人的层**，不是放开模型。
- **N 必要**：没有它，梳理人永远只能看模型的树；且不改这一层，第 3 项的题卡挂靠就没有稳定锚点。更轻替代「只给节点加批注」不够——批注改不了结构。
- **对三类人**：A 备考——可以按自己的复习顺序重排章节；B 梳理——**核心诉求**；C 存储——改动落盘，不因重分析丢失。

### 第 2 项 · 题卡结构化（147 道原题从陈列馆变成能做的题）

- **干什么**：`build-lesson-cards.mjs` / `build-assignment-cards.mjs` 产出的卡片补四个字段：`options[]` / `answer` / `rationale` / `pitfalls[]`。来源优先从转录语料的原题原文抽（原书作业本就有选项），抽不到的**诚实标 `needsReview`**，不编。
- **R 合理**：`core/practice.js:30-37` 的 questionKey 已经按「题面+选项+答案」设计好了——是生产端没喂饱，不是判分层缺能力。
- **C 正确（锚点）**：亲验 23 个卡片 JSON / 147 题，`options`、`rationale`、`pitfalls` 全部 0 命中；能判分的只有 analysis.json 的 12 道自编题。
- **N 必要**：这是备考人最贵的一道坎——最想做的课后原题做不了。更轻替代「只给作业卡加个答案文本」不够，进不了 SRS。
- **对三类人**：A 备考——**核心诉求**，原题能选能判能订正；B 梳理——每道题挂回 `pointPath`，知识点不再是孤岛；C 存储——有稳定 key，复习进度不怕重分析。

### 第 3 项 · 作业入口接线（22 组卡从 API 走到界面）

- **干什么**：书内页签或题型页加「作业」分组，点开按 5 份作业列题；练习页支持按「作业」筛选而不是只能练全部。
- **R 合理**：数据已在（`/api/core/books/:id/cards` 实测 22 组），只差界面入口。
- **C 正确（锚点，11-27 实施后纠正）**：初版写「书内全页无作业字样」是**假阳性**——真机没点进「题型」页签。实测 5 份作业组就在题型页最底部，混在 27 个折叠组里默认全收起。API 返回 22 组 / 147 题属实。
- **N 必要**：入口已在但藏太深，学生照样找不到。把作业提升为独立页签仍是最小成本最高收益的一项。
- **对三类人**：A 备考——**直接可用**；B 梳理——作业作为知识点的应用证据可见；C 存储——多一个可检索维度。

### 第 4 项 · 一份「考点包」同时满足打印 / 导出 / 备份 / 找回

- **干什么**：新增一个生成物 `exam-pack.json` + 对应 HTML 打印页，内容 = 用户结构（第 1 项）+ 结构化题卡（第 2 项）+ 每点一句话考点 + 原图引用。同时修 `lib/backup.js:22` 白名单漏的三个字段；搜索结果到上限时明确告诉用户「还有 N 条未显示」。
- **R 合理**：三类人最终都要「带走」——学生要一页纸，梳理人要可复用文件，存储人要能恢复。一个包三种用法，比做三个功能省。
- **C 正确（锚点）**：`grep 小抄|cheatsheet` 零命中；`lib/backup.js:22` SETTINGS_KEYS 漏 `visionModel`/`deepDive`/`tickEveryRounds`；`lib/search.js:7,20,88` 上限 80 且截断无提示。现行备份上限 180MB（`lib/backup.js:20`，旧版 64MB 的坑已修）。
- **N 必要**：没有它，작完的题、改好的结构还是困在 app 里；换机器就丢。更轻替代「只加打印页」不满足存储人。
- **对三类人**：A 备考——考前打印一页纸；B 梳理——导出保留完整结构与 desc；C 存储——**核心诉求**，备份不丢字段、检索有边界提示。

### 第 5 项 · 自动备份（保守版）

- **干什么**：书级数据变更时写一份本地快照（只在本机 `library/_snapshots/`，不联网、不上传），保留最近 N 份；不引入云服务。
- **R 合理**：`library/` 已 gitignore，机器故障全丢；自动备份是存储人的底线。
- **C 正确（锚点）**：全仓 `grep setInterval.*backup|定时备份|自动备份` 零命中。
- **N 必要**：手动导出靠人记得——这恰恰是「存储」人群最不信任的地方。保守版只写本机，成本可控。
- **对三类人**：A/B——改坏了能回退；C——**核心诉求**。

## 三、冲突裁决（R/C/N 三关汇总）

| # | 改动 | R | C | N | 结论 |
|---|---|---|---|---|---|
| 1 | 用户结构层 | 合定位（模型树为底稿，用户层另存） | 锚点 4 处（analyze.js / fusion-decisions / mindmap.js / persistMapState） | 必要，否则题卡无锚点 | **合** |
| 2 | 题卡结构化 | 合定位（生产端补字段，不改判分层） | 23 文件/147 题，三字段零命中 | 必要，备考核心 | **合** |
| 3 | 作业入口接线 | 合定位（数据已有） | API 22 组 vs UI 0 入口 | 必要，最小成本 | **合** |
| 4 | 考点包（打印/导出/备份） | 合定位（一物三用） | 小抄零命中 + 白名单漏 3 字段 + 搜索截断无提示 | 必要，存储核心 | **合** |
| 5 | 自动备份（保守版） | 合定位（本机快照） | 零命中 | 必要，存储底线 | **合** |

**被否决的候选**（不硬加）：
- 「让模型自由改结构」→ 否：当年 `analyze.js:70-76` 禁止是有理由的（防模型乱改名/合并章），现在加的是用户层，不动模型契约。
- 「上云同步」→ 否：项目定位本地优先，引入账号/云服务是另一个产品，R 不过。
- 「全库倒排索引」→ 否：搜索 80 条截断先给明确提示即可，倒排是过度工程，N 不过。

## 四、实在的、计划落地后的结果效果（可验收）

> 不写「提升体验」。每条都是改完后用户能看到的具体变化 + 怎么验。

| # | 改完以后用户看到什么 | 怎么验（可复现判据） |
|---|---|---|
| 1 | 导图节点能右键改名、拖拽换父；改完刷新还在；点「恢复模型结构」可回到原树 | 真浏览器改一个节点名 → reload → 名字还在；点恢复 → 回到模型原名；`structure.json` 落盘且 analysis.json 未被改写 |
| 2 | 作业题能选 A/B/C/D，提交后显示对错 + 分步解析 + 易错；做错自动排下次复习 | `/api/core/books/:id/cards` 返回的题含 options/answer/rationale/pitfalls；`cards/*.json` 里 147 题中可判分题从 0 → ≥ 100（抽不到原文的诚实标 needsReview，不凑数） |
| 3 | **已做（v1.7.3）**：书内「作业」独立页签，5 份 22 题默认全展开、题目原图直显；**练习页按作业筛选未做**（依赖第 2 项零选项，无意义） | 真浏览器点「作业」页签 → 5 份作业组全展开 → 22 题真进 DOM、题型页 27 组未被改坏；`check-flow-fusion` G1–G5 + 真机 11/11 |
| 4 | 设置页一点「导出考点包」得到一份 HTML：左边是可打印的一页纸考点，右边是完整结构 + 题卡 + 原图；备份恢复后 visionModel/deepDive/tickEveryRounds 不回默认 | 导出 HTML 打开有打印样式；备份→清库→恢复→`/api/settings` 三字段值与备份前一致；搜索超 80 条时界面写明「还有 N 条未显示」 |
| 5 | 每次改书自动在本地留一份快照，改坏了能一键回到上一份 | 改一个节点 → `library/_snapshots/` 多一份；点「恢复上一版」→ 节点名回退；不联网（抓包 0 外部请求） |

**三类人同时满足的判据（统一验收）**：
拿同一本《理论力学》，一个备考学生、一个做知识梳理的人、一个存考点的人，三个人各走一遍：
- 学生：导入作业 → 在「作业」页签做 4 道原题 → 答错 1 道 → 明天在「今日到期」看到它。（对应 2+3）
- 梳理者：把「3.1 汇交力系」从第三章拖到第二章下 → 刷新还在 → 导出 HTML 结构一致。（对应 1+4）
- 存储者：导出考点包 → 换一份空库 → 导入恢复 → 三个设置字段、改过的结构、做题记录全在。（对应 4+5）

三个人走的是同一个 app、同一本书、同一份数据——这就是「三者全部满足」的实在含义。

## 五、KNOWN-LIMITATION（计划阶段就写清，不事后找补）

- 24 份课件零文本层，原题卡能否抽出 options 取决于转录质量；抽不到的必须标 needsReview，**不许编选项**。统一验收里「≥100 道可判分」是目标，若实测达不到，就如实降低并说明原因。
- 用户结构层「恢复模型结构」会丢人工改动，需要二次确认（不可逆动作先问斯瑞这条铁律在 UI 上也要兑现）。
- 自动备份只在本机，不防硬盘物理损坏；不宣称「数据安全」。
- 本轮**只计划不实施**：以上五项均未改代码，QA 数字全部是预期判据，不是已达成结果。
- **11-27 实施更新**：用户说「就这样做」后，第 3 项已落地（v1.7.3：作业独立页签 + 默认展开，复用 `renderCardGroups` 加 `onlyAssignment` 过滤）；其余四项仍是计划。练习页「只看作业」筛选随第 2 项一起做——147 题零 `options` 时筛出来也判不了分。
