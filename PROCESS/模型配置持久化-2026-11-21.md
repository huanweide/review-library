# 模型配置持久化（2026-11-21）

> 用户原话：「告诉你了就用环境变量的硅基流动（可保存住，可找模型，可设置）保存了 使用 继续修复」

## 一、要解决的问题（用户视角，不是技术视角）

| 现象 | 用户的感受 |
|---|---|
| 分析要粘一次 key、生成考点大全要粘一次、生成考纲再粘一次 | 「我不是在用工具，是在喂工具」 |
| localStorage 只记得地址和模型，从不记得 key | 每次刷新都像第一次用 |
| 设置页只有主题和密度，没有模型配置 | 「可设置」无从谈起 |
| 模型名要凭记忆敲（`deepseek-ai/DeepSeek-V4.1-Flash` 谁记得住） | 「可找模型」无从谈起 |

## 二、定调（判据，不再重议）

1. **密钥只有一处权威位置：服务端。** 前端结构性拿不到原文（只有掩码），因此也不存在「前端忘了带 key」这种失败模式。
2. **优先级＝本次请求显式传的 > 配置文件 > 环境变量。** 显式传的赢，因为当场换 key 是更强意图；配置文件赢环境变量，因为它是用户手填的最近动作，环境变量是默认值。来源要能被界面说出来。
3. **「保存了使用」= 粘一次就够。** 成功调用之后自动把这次用的地址/模型（含当场粘的密钥）记住，不需要用户再点一次「保存」。
4. **「可找模型」= 按钮触发，不是打开就请求。** 一次 `/models` 是网络请求，不该在用户没要求时发出去。
5. **「可设置」= 设置页有一等位置。** 只藏在分析对话框里的配置，等于用户每次都要重新找一遍。

## 三、落地

| 层 | 文件 | 做了什么 |
|---|---|---|
| 配置 | `core/settings.js`（新） | 解析优先级、掩码回显、原子落盘、注册表兜底、模型分类 |
| 传输 | `lib/llm.js` | `fetchModels()`（GET /models 归一） |
| 接口 | `server.js` | `/api/settings`、`/api/settings/test`、`/api/models`；四处入口统一补 `cfg` |
| 协议 | `core/app-host.js`、`core/request.js`、`core/index.js`（`cachedOnly`） | 缺省 cfg 可用；页签探测不花钱 |
| 前端 | `workbench/src/llm-config.js`（新）、`host.js`、`views.js`、`bookspace.js` | 共用控件 / 共用对话框 / 已配置零表单 |

- `node tools/check-compose-chain.mjs` → 6/6（旧断言「必须每次弹框要 key」按用户意图重写）
- `npm test` → 24/25（唯一红＝Node24/Windows undici 退出断言，断言 28/28 全过，属环境噪声）
- 其余七组判别脚本全绿：flow-fusion 25、p1-fusion 14、progressive-fusion 17、analysis-robustness 4、empty-state 3、structure-fidelity 9
- 真机 HTTP：`/api/settings` 回 `hasKey=true / keySource=env / keyHint=sk-…qkoj`；`/api/models` 回 92 个（56 chat / 5 vision）；`/api/settings/test` 真发最小对话 `ok:true`
- 真机浏览器（playwright-cli）：设置页「找模型」→ 92 个、选中即填入；分析对话框预填 + 掩码回显；点「生成考点大全」**不弹任何框**，直接产出 4 章 43 条并落盘 `documents/digest.json`；重载后控制台 **0 error 0 warning**

## 五、已知边界（不夸大）

- Electron 形态暂未接配置存储：`host.settings()` 返回 `unsupported`，界面文案明确说「仍需手动填」，不假装已配置。
- DSH 插件形态的 `/review-analysis/api/settings` 未实现，同样走降级分支。
- 「找模型」不做「哪个模型更好」的判断，只做「能不能对话 / 能不能看图」的名字级分类；选错仍可手输模型名。
- 注册表兜底只在 Windows 生效（其它平台读 `process.env` 即可）。
- 本轮未处理：书架上「5」（0 资料）、「E2E书」这类测试残留（删除属破坏性操作，等用户点头）。
