## 一、修掉的 bug

### 1. 默认首页 `/` 相对路径全部 404（服务层）

- **现象**：打开 `http://127.0.0.1:5178/` 只有「正在启动应用…」空壳；控制台 5 个 404：`/src/style.css`、`/src/main.js`、`/manifest.webmanifest`、`/icons/icon.svg`。
- **根因**：`server.js` 把 `/` 直接返回 `workbench/index.html` 的**内容**，但 HTML 里是相对路径（`./src/main.js`）。浏览器按当前 URL `/` 解析成 `/src/main.js`；workbench 只挂在 `/workbench/` 前缀下，于是全部 404。
- **修法**：`server.js` 的 `/` 改成 `302 Location: /workbench/`，由目录 URL 承载相对路径（`workbench/index.html` 本身不动）。
- **验证**：`GET /` → 302；`/workbench/`、`/workbench/src/main.js`、`/workbench/src/style.css`、`/workbench/manifest.webmanifest`、`/workbench/icons/icon.svg`、`/api/app/manifest` 全部 200。

### 2. DSH 插件 Host 半边装载失败（配置层）

- **现象**：左侧栏「复习分析」图标在，但 `review_analysis` 工具不可用、面板内嵌应用空白。
- **根因**：`plugins/dsh-review-analysis/cordis.patch.yml` 的 `projectRoot` 还指向旧仓库 `C:/Users/Administrator/Desktop/rlbuild`（那里面没有 `workbench/`，新版统一核心也已迁到 `复习资料图书馆/`）。`plugin_manager list_plugins` 的直接证据：
  `include:review-analysis` → `fiberPhase: failed`，`diagnostic: 找不到统一核心能力清单：C:\Users\Administrator\Desktop\rlbuild\core\capabilities.js`。
- **修法**：`projectRoot` 改为 `C:/Users/Administrator/Desktop/agent program/复习资料图书馆`；已安装副本 `~/.dsh/local-plugins/dsh-review-analysis/cordis.patch.yml` 同步。
- **生效方式**：`plugin_manager(set_plugin, target=include:review-analysis, enabled=false → true)` 会重读 bundle patch 并重新 apply（本轮实测：`fiberPhase` 由 `failed` 变 `active`，无需重启整个应用）。
- **验证**：Host `Tool.listTools` 已含 `review_analysis`；`Config.listConfigs` 有 `include:review-analysis`；Client Slots：`sidebar.panellist` 有 `review-analysis`（order 30，active），`main` 有 key `review-analysis`。
