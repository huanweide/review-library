## 一句话结论

**地基是硬的，界面是工程师的。**
后端协议、测试门禁、图片原字节、SRS 调度这些「难做对的部分」都对；但界面每一处都在向用户解释系统（action 名、书库边界、哈希 key、技术文案），而不是帮用户完成「我今天该学什么」。**最严重的一处是：真正做题的练习页没有任何图片，而题干写着「根据图中」。**

## 一、架构认知

### 1.1 分层实况

```
数据层   library/books/<id>/        12MB · 7 个书目录
           book.json（元数据+files[]）
           analysis.json（导图/题型/考点）
           images.json + images/（原字节，SHA 去重）
           practice.json（SRS 卡片，仅演示书有）
           documents/（考点大全/考纲/幻灯片）
   ↓
核心层   core/*.js                  6324 行（含前端）
           capabilities.js  单一能力真源（12 action，对齐 Anki proto 做法）
           app-host.js      action 分发 / api/app/action
           analyze.js       分析（提示词+校验+围栏+quoteAudit+deepDive）
           images.js        原字节抽取 + SHA 去重 + primaryImages
           image-vision.js  视觉理解（看图→写 vision 字段）
           practice.js      SRS（applySchedule/dueKeys/summarize）
           corpus-guard.js  注入围栏
           bookStore.js     store 层（listBooks 只认 book.json.files）
   ↓
协议层   两套并存（刻意）
           ① /api/app/action  {action,payload}  → workbench 用
           ② /api/books + /api/core/*          → 全功能台用
   ↓
表现层   workbench/src/              3434 行
           bookspace.js  1366 行（7 个 tab 全在这一个文件里，占前端 40%）
           views.js       558 行（书架 + quiz/practice/due/attempt/rate）
           mindmap.js     331 行
           style.css      581 行
```

### 1.2 架构判断

**做对的（不动）**

| 决策 | 证据 | 为什么对 |
|---|---|---|
| 能力清单单一真源 | `capabilities.js` 12 action + J1 同步测试 | 五入口（本地/DSH/CLI/Electron/插件）不会各写一套 |
| 图片存原字节不重绘 | `images.json` 的 sha256 与源文件一致 | 3 万星 Anki 也是 `bytes data` + 独立 shape，同构 |
| 题目先答后揭 | `quiz` 返回字段实测无 answer/solution | 防泄底在协议层，不靠前端自觉 |
| 学习闭环真跑通 | attempt→判卷正确→rate 排程→due 复核一致 | 机制完整，不是空壳 |

**三个真实的架构风险**

| 风险 | 量化证据 | 后果 |
|---|---|---|
| **R1 单文件承载全部 tab** | `bookspace.js` 1366 行 / 73KB，7 个 tab 的渲染、状态、交叉索引全在里面 | 改任一 tab 都要通读整文件；已出现「看图区改一处、题型页跟着变」的耦合 |
| **R2 两套 UI 并存** | `book` 走 bookspace（7 tab、隐藏侧栏）；`quiz/due/practice` 走 views.js（侧栏回归、面包屑变「学习」、卡片样式不同） | 用户从题型页点「去练习」会「换了一个 App」；同一本书两套编号 |
| **R3 服务无自愈** | 本次体检开始 5178 已 DOWN（会话回收），需手动起 | 用户打开就是白屏，且不知道原因 |

## 三、端到端走查：12 个真实问题

按用户实际路径记录，附 DOM 证据。

### P0 · 直接破坏验收标准

**#1 练习页零图片，「根据图中」的题做不了**
- 路径：书内 → 题型（第 3 题有图，直嵌题干下）→ 点「去练习」→ 练习题目页
- 证据：练习页 `document.querySelectorAll('img').length === 0`；`quiz` 返回字段只有 `key/type/subtype/stem/options/difficulty/pointPath/pointId/auto`，**没有 imageIds**
- 影响：用户验收标准 3 明确要「有些题目必须要有图片才能做」。这句话现在只做到一半——**有图的地方不是做题界面，做题的地方没图**
- 根因：`core/practice.js` 的 `flatten()` 只取文本字段，图片关联没进题目契约

**#2 考点大全 / 考纲默认是空的**
- 证据：点进两个 tab，`.bs-doc-empty` 提示「还没有考点大全」「还没有考纲」，`textLen` 仅 118/120 字符
- 影响：验收标准 2 要「生成各种相互串联的思维导图、**考纲知识点大全**」，7 个 tab 里 2 个空着
- 判断：分析已花 5 分钟跑完 LLM，却没顺手产出这两份；若是 token 预算考量，界面必须说清「为什么分开、点一下要多久」

**#3 题目编号有两套，无法互相引用**
- 题型页：每个题型分类内序号重置（第 1、2 题之后又出现「第 1 题」）
- 概览页：图片索引写「用于第 13 题」（全局编号）
- 影响：学生没法说「第 13 题」，也没法和同学对答案

### P1 · 显著影响可用性

**#4 侧栏把后端 action 名当装饰露给用户**
- 证据：每个菜单项右侧灰字 `list` `get` `analyze` `create` `add` `practice` `quiz` `due` `attempt` `rate`
- 判断：对用户零信息量，是开发视角泄漏；且「提交作答」「四档自评」直接做成菜单，用户不知道何时该点

**#5 顶部常驻一段「书库边界」技术说明**
- 内容：「本应用读的是统一核心 core 的库…旧版全功能工作台…是另一套元数据格式…」
- 判断：这是写给开发者的架构注记，占掉了首屏黄金位置

**#6 书架首屏 400px 空白，没有学习信息**
- 证据：6 张卡排 4+2，下方整片空白；没有「今日待复习 N 张」「上次学到哪」「本周进度」
- 判断：书架是首页，用户来这里想的是「今天学什么」，界面给的是「你有 6 本书」

**#7 导图节点标题被省略号截断 + 描述不可读**
- 证据：「(1) 正态分布曲线的两个…」「(3) 两个可能服从正态分…」；节点内描述 `font-size:10px` 灰色
- 影响：第一眼读不全，要靠悬停 tooltip；描述像「有信息但看不清」

**#8 导图实心块溢出画布**
- 证据：左下「概率统计·正态分布…」「任务1·认识正态分…」两个蓝色实心块，第二个被画布底边裁掉一半

**#9 章 chips 把作业流程当知识骨架**
- 证据：chips 为「全书·4章 / 任务1·认识正态 / 任务2·发现生活 / 附：数据与工具说明 / **提交清单**」
- 根因：上一轮为「完整性优先」改成「资料自带结构一律照搬」，副作用是把作业提交清单当成了知识章节

**#10 练习页露哈希 key**
- 证据：题目卡显示「第 1 题 选择题 d0f8d18cad413792」
- 判断：`key` 是内部去重标识，不该出现

### P2 · 打磨项

**#11 概览页摘要为空**：`（模型没有给摘要）`——概览最该有「这本书讲什么」
**#12 垃圾数据占书架**：标题为「5」的空书（0 资料）、「E2E书」（测试用）出现在正式书架

## 五、一个更重要的结论

**门禁 24/25、判别脚本 52 项全绿，但用户体验仍有 12 个真问题。**

这不是说测试没用，而是说测试测的是「代码契约对不对」（能力同步、引文命中、围栏闭合、结构保真），没测「用户能不能完成一件事」。上一轮我加的判别测试全都围绕**数据正确性**，没有一条围绕**路径可完成性**。

建议补一类测试：**路径测试**——从书架进书→做题→看答案→评分→到期复查，每一步断言「屏幕上出现了用户需要的东西」。当前 #1（练习页无图）就会被这类测试立刻抓住。

## 八、复检结果（2026-11-21 12:40，紧接上一节的修复轮）

用户指定优先：**便捷三项（2 个 tab 空 / 题号两套 / 练习跳出去换界面）+ 复习效果到满分**。
按 maxloop 全流程执行：阶段零外查 → 计划公示 → 判别测试 baseline 红 → 修复 → 真机 → 门禁。

### 8.1 外部基准推翻了我最初的方案

原计划「答完自动按对错给分」。查完基准后否掉了：

| 基准 | 原文锚点 | 结论 |
|---|---|---|
| Anki 论坛用户（2026-06） | "I personally want to study 99.5% of times I open the app… The review should open immediately upon clicking on the pack" | 「点开再点一次」被判多余 |
| 中文技术分析 | "Anki 的复习界面只有四样东西…这种极简，本质是在强制剥离所有干扰认知判断的噪声" | 练习不能做成第 8 个 tab |
| Anki 官方对比系列（3 份独立来源） | "A brand-new card offers four grades: Again, Hard, Good, and Easy"；"the app shows you the next interval before you grade yourself" | **两家都用四档手动**，没人做自动评分；正解是评分前显示间隔 |
| qiaomu（6537★） | 一份资料一次触发全出八种产物 | 考点大全/考纲应自动补齐 |

### 8.2 六项落地与真机证据

| 项 | 改法 | 真机证据 |
|---|---|---|
| A 练习页带图 | `practice.flatten` 增加 `imageIds`（脱敏模式也带——图是题面不是答案） | 练习页 `figs=3`，第 3 题下方显示 3σ 图 |

| C 练习不换壳 | `quiz/practice/due/attempt/rate` 纳入 `bs-focus`；练习页加回书链接与看导图 | `sidebar=none`、`body=bs-focus`、`← 回到《概率统计》` |
| D 四档预览 | `previewRatings` 用**排程前**状态算四档，`attempt` 返回 `nextIntervals/scheduledBy/currentLabel` | 「答对 · 记得 → 1 天后再见」+「重来·马上 / 有点难·15小时后 / 记得·1天后 / 很简单·3天后」 |

| F 首页学习状态 | `list` 每本带 `dueCount`；书架卡与标题栏显示 | 书架「待复习 1」、页头「待复习 1」、点击直达 `#/due` |

### 8.3 顺手修掉的四个真 bug（都不在原计划里）

1. **纯字母答案判不了卷**：`parseAnswer` 正则漏 `|$`，标准答案写成 `B` 时永远退化成人工自评；而 `normalizeGiven` 早就支持纯字母——两处口径不一致。实测四种写法（`B` / `B. 8 个` / `b` / `B、选项`）修后全部能判。
2. **书卡渲染两遍**：在渲染中途同步 `set({dueTotal})` 触发 `subscribe → renderView`，第一遍的 `appendChild` 落到新容器，界面出现 12 张卡。改 `setTimeout(..., 0)`。
3. **到期页是数据块**：「待复习 N」点进去原先是 `kv()` + `dataBlock()` 的调试输出。抽出 `renderQuizCards` 供练习页与到期页共用。
4. **练习页露哈希 key**：`q-key` 显示题目内部 id，已移除。

### 8.5 为什么复习效果不是 10（诚实边界）

1. **E 项未做真机 LLM 全链路**：`autoCompose` 的接线由判别测试锁住（调用点、两个 kind、失败 catch），手动生成路径上一轮已真机验证可用，但「分析完自动出现两份产物」需要一次真实分析（约 2 分钟 LLM），本轮未烧。
2. **概览页摘要仍为空**：`（模型没有给摘要）`，属于分析提示词产出问题，未在本轮范围。
3. **真实书仍无复习记录**：本轮只在演示书造了 1 张到期卡做验证；概率统计/工程材料/提示词工程三本书的 `practice.json` 依旧不存在。机制通了，但「用户真的会用它复习」只能靠后续使用验证，不能靠改代码断言。
